# HarambeeOne Repository Guide

This guide explains what each repository area contains, which parts are operational, and which files are references or generated artifacts. Read it with the canonical [MVP roadmap](MVP_ROADMAP.md), which remains authoritative for delivery status.

## Runtime request path

```text
Browser
  -> Next.js application (apps/web)
  -> same-origin authenticated API gateway
  -> FastAPI service (apps/backend)
  -> Supabase PostgreSQL
```

Firebase Authentication establishes a server-owned session cookie. FastAPI maps the Firebase subject to a stable internal user UUID, then independently resolves the active school membership and permission for every operational request. Supabase PostgreSQL remains the temporary database host, stores financial truth, applies row-level security, and preserves immutable evidence through constraints and triggers until the SQL Connect cutover slice.

## Active applications

### `apps/web`

The active Next.js 15 and React 19 application. It contains the bursar workspace, authentication entry points, guardian and donor portals, public Support experience, and same-origin server gateways.

- `app/` contains route segments and page-specific interfaces.
- `components/` contains shared shells, authentication controls, notifications, and presentation primitives.
- `lib/` contains session-aware API clients, Firebase authentication clients, temporary Supabase compatibility clients, school selection, period state, and reusable browser/server utilities.
- `middleware.ts` performs lightweight route/session coordination; final authorization remains server-side.
- `public/` contains browser-served brand assets.
- `scripts/next-with-root-env.mjs` loads root configuration before invoking Next.js.

CSS is split by workflow. `globals.css` supplies the shared visual system, while feature stylesheets keep complex workspaces isolated and maintainable.

### `apps/backend`

The authoritative FastAPI service and PostgreSQL migration project.

- `src/harambeeone_api/main.py` composes the API, health endpoints, middleware, and workflow routers.
- `auth.py` verifies Firebase sessions, resolves stable internal identities, and derives tenant permissions from database membership. A non-production Supabase verifier remains only as a rollback boundary until final cutover.
- `models.py` defines SQLAlchemy persistence models; Alembic migrations remain the deployed schema history.
- `financial_reporting.py` owns the canonical exact-decimal learner and school financial equation.
- Workflow modules such as `billing.py`, `finance.py`, `reconciliation.py`, `periods.py`, and `reports.py` implement bursar operations.
- Support modules are isolated from normal bursar finance and cannot bypass ledger, consent, or publication controls.
- `migrations/versions/` contains ordered schema, RLS, constraint, index, trigger, and data-transition changes.
- `tests/` covers business rules, authorization, tenant isolation, retry safety, and rollback.
- `scripts/verify_*.py` checks PostgreSQL-specific guarantees against the configured Supabase database.
- `cloudsql/bootstrap.sql` supplies locked compatibility objects so the complete historical
  Alembic chain can be rehearsed on empty Cloud SQL, while `scripts/migrate_cloudsql_data.py`
  performs an explicit data-only transfer and deterministic parity proof.

Money is represented with `Decimal` in Python and `numeric(18,2)` in PostgreSQL. Posted financial history is corrected through compensating entries rather than mutation or deletion.

## Reference applications and packages

### `apps/api`

A legacy NestJS/Prisma implementation retained as a migration reference. It is not started by the root development command, and new operational endpoints must not be added here.

### `packages/shared`

A small TypeScript vocabulary shared by older workspace code. Active Python API contracts are defined by Pydantic schemas and documented endpoints.

### `packages/soroban`

An experimental Soroban education-funding contract with reproducible test snapshots. Blockchain settlement remains deferred and this package is not part of the active bursar request path.

## Documentation and evidence

### `docs`

- `MVP_ROADMAP.md` is the canonical delivery plan and status record.
- `ARCHITECTURE.md` defines boundaries, topology, and financial authority.
- `API_OVERVIEW.md` explains API groups and authorization expectations.
- `SECURITY.md` records the security and privacy baseline.
- `INTEGRATION_API.md` defines versioned external exchange contracts.
- `INTEGRATIONS.md` records provider integration boundaries.
- `HARAMBEE_SUPPORT_EXPANSION_PLAN.md` documents the controlled Support workflow.
- `ENTERPRISE_INTEROPERABILITY_PLAN.md` documents multi-unit access, transfer, and exchange design.

### `SUPPORT`

Product documents, diagrams, and brand assets supplied as discovery evidence. Word documents and images are binary source material, not executable code and not authoritative over the current roadmap.

### `stitch_harambeeone_education_finance_platform`

Stitch-generated visual references. Each design folder may contain a screenshot and HTML mock-up. These files are inspiration and comparison material; they are not production routes and should not be bulk-copied into the active application.

## Tooling and generated material

- `scripts/setup.sh` is a convenience bootstrap for compatible Unix shells.
- `.agents`, `.aider-desk`, `.augment`, `.autohand`, `.bob`, and `.codestudio` contain tool-specific copies of the Supabase skill.
- `data/skills/supabase` contains the source skill material and feedback references.
- Generated locks, build directories, caches, screenshots, Word documents, and images should not receive hand-written source comments.

## Change routing

| Change | Primary location |
| --- | --- |
| Bursar interface | `apps/web/app`, with shared UI in `apps/web/components` |
| Business rule or endpoint | `apps/backend/src/harambeeone_api` |
| Persistent schema or database control | New Alembic migration |
| PostgreSQL security verification | `apps/backend/scripts/verify_*.py` |
| Business-rule regression | `apps/backend/tests` |
| Product status | `docs/MVP_ROADMAP.md`, only after verification |
| External exchange contract | `docs/INTEGRATION_API.md` and integration module |
| Deferred blockchain experiment | `packages/soroban`, only after roadmap authorization |

## Files that should not be manually annotated

Do not insert comments into formats that do not support them or files generated by tools. This includes JSON, lockfiles, PNG, ICO, DOCX, compiled output, framework declarations, and test snapshots. Document those artifacts in Markdown guides instead of altering their contents.

## Required verification

Documentation-only changes should at minimum pass Markdown/link review and `git diff --check`. Source comments must additionally pass the relevant formatter, linter, type checker, tests, and production build because misplaced comments can affect directives, generated syntax, or compilation.
